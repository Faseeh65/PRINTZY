# Production Deployment and Operations

## Cloudflare Workers (Production)

Printzy is deployed to **Cloudflare Workers** using TanStack Start with Nitro's `cloudflare-module` preset. Deployments trigger automatically via Cloudflare Workers Builds on every git push to `main`.

### Architecture & Build Outputs

- **Package Manager**: Bun (`bun`).
- **Build Command**: `bun run build`
- **Output Artifacts**:
  - Worker server entry: `.output/server/index.mjs`
  - Static client assets: `.output/public`
- **Configuration**: [`wrangler.jsonc`](../wrangler.jsonc) defines Worker bindings, routes, smart placement, and asset directory mapping (`.output/public`).

### Automated CI/CD (Cloudflare Workers Builds)

1. **Dashboard Build Settings**:
   - **Framework Preset**: None / Custom
   - **Build Command**: `bun run build`
   - **Deploy / Static Assets Directory**: `.output/public`
   - **Root Directory**: `/`
2. **Rollbacks**:
   - Cloudflare Workers supports instant zero-downtime rollbacks.
   - To roll back to an earlier deploy: Navigate to **Cloudflare Dashboard → Workers & Pages → printzy → Deployments**, select the desired past deployment, and click **Rollback**.

### Environment Variables and Secrets

#### Public Build-Time Variables (`VITE_*`)
Set these in **Cloudflare Dashboard → Workers & Pages → Settings → Variables and Secrets** (or during the build step):
- `VITE_SITE_URL`: `https://printzy.site` (canonical HTTPS apex).
- `VITE_APP_ENV`: `production`
- `VITE_TURNSTILE_SITE_KEY`: Public Cloudflare Turnstile site key.

> [!WARNING]
> Any variable prefixed with `VITE_` is statically injected into the client-side JavaScript bundle at build time. **Never** place private API keys, database credentials, or secret tokens in `VITE_*` variables.

#### Private Runtime Secrets
Set these as encrypted Worker secrets using Wrangler CLI or via **Cloudflare Dashboard → Workers & Pages → Settings → Variables and Secrets (Environment Variables / Secrets)**:
- `RESEND_API_KEY`: API key for sending quote request emails.
- `TURNSTILE_SECRET_KEY`: Cloudflare Turnstile secret key for server-side token validation.
- `SENTRY_DSN`: (Optional) Sentry server/Worker DSN for error telemetry.

To set secrets via CLI:
```sh
npx wrangler secret put RESEND_API_KEY
npx wrangler secret put TURNSTILE_SECRET_KEY
```

### DNS and Domains

- **Canonical Apex Domain**: `https://printzy.site`
- **WWW Subdomain**: Cloudflare DNS CNAME pointing to apex with a 301 redirect rule to `https://printzy.site`.
- **Legacy Domain Redirects**: The Worker automatically issues permanent 301 redirects for `printzy.pk` and `www.printzy.site` to `https://printzy.site`.

### Rate Limiting and Security

The Worker binds edge-local rate limiters:
- **General requests**: 60 requests/minute per client IP.
- **Sensitive endpoints** (e.g. quote requests): 5 requests/minute per client IP.
- `/healthz` is exempt from rate limiting.

### Static Assets and Caching

- Static assets in `/assets/` generated by Vite contain content hashes and are served with `Cache-Control: public, max-age=31536000, immutable`.
- Cloudflare static asset responses are governed by [`public/_headers`](../public/_headers).
- SSR HTML pages are server-rendered with `max-age=0, s-maxage=60, stale-while-revalidate=300`. Responses setting cookies or handling mutations must never be cached.

### Health Check

`GET /healthz` and `HEAD /healthz` perform liveness checks and return `no-store` responses.

## Optional VPS or Docker Path (Self-Hosted Reference)

[`Dockerfile`](../Dockerfile) builds Nitro with the `node-server` preset and runs the generated Node server on port 3000:

```sh
docker build -t printzy .
docker run --rm -p 3000:3000 printzy
```

Deploying behind a reverse proxy (e.g. Nginx, [`deploy/nginx.conf`](../deploy/nginx.conf)) is supported for containerized environments, but Cloudflare Workers is the primary and supported production target.
